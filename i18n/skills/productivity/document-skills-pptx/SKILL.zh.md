# PPTX创建、编辑和分析

## 概述

用户可能要求您创建、编辑或分析演示文稿的内容。.pptx文件本质上是一个包含XML文件和其他资源的ZIP存档，您可以读取或编辑。您有不同工具和工作流程可供不同任务使用。

## 读取和分析内容

### 文本提取
如果您只需要读取演示文稿的文本内容，应将文档转换为Markdown：

```bash
# 将文档转换为Markdown
python -m markitdown 路径-to-file.pptx
```

### 原始XML访问
您需要原始XML访问权限以获取注释、演讲者备注、幻灯片布局、动画、设计元素和复杂格式。对于这些功能中的任何一项，您都需要解包演示文稿并读取其原始XML内容。

#### 解包文件
`python ooxml/scripts/unpack.py <office_file> <output_dir>`

**注意**：unpack.py脚本位于项目根目录相对路径的`skills/pptx/ooxml/scripts/unpack.py`。如果脚本不在此路径存在，请使用`find . -name "unpack.py"`来定位它。

#### 关键文件结构
* `ppt/presentation.xml` - 主要演示文稿元数据和幻灯片引用
* `ppt/slides/slide{N}.xml` - 单个幻灯片内容（slide1.xml、slide2.xml等）
* `ppt/notesSlides/notesSlide{N}.xml` - 每个幻灯片的演讲者备注
* `ppt/comments/modernComment_*.xml` - 特定幻灯片的注释
* `ppt/slideLayouts/` - 幻灯片布局模板
* `ppt/slideMasters/` - 主幻灯片模板
* `ppt/theme/` - 主题和样式信息
* `ppt/media/` - 图片和其他媒体文件

#### 字体和颜色提取
**当给定一个要仿制的示例设计时**：始终使用以下方法首先分析演示文稿的字体和颜色：
1. **读取主题文件**：检查`ppt/theme/theme1.xml`中的颜色（`<a:clrScheme>`）和字体（`<a:fontScheme>`）
2. **检查示例幻灯片内容**：检查`ppt/slides/slide1.xml`中的实际字体使用（《a:rPr>`）和颜色
3. **搜索模式**：使用grep在所有XML文件中查找颜色（`<a:solidFill>`、`<a:srgbClr>`）和字体引用

## 创建新的PowerPoint演示文稿（无模板）

当从头开始创建新的PowerPoint演示文稿时，使用**html2pptx**工作流程将HTML幻灯片转换为PowerPoint，并保持准确的位置。

### 设计原则

**至关重要的**：在创建任何演示文稿之前，分析内容并选择适当的设计元素：
1. **考虑主题内容**：这个演示文稿是关于什么的？它暗示了什么基调、行业或氛围？
2. **检查品牌**：如果用户提到了公司/组织，考虑他们的品牌颜色和身份
3. **将调色板与内容相匹配**：选择反映主题的颜色
4. **说明你的方法**：在编写代码之前解释你的设计选择

**要求**：
- ✅ 在编写代码之前，说明你的基于内容的设计方法
- ✅ 只使用Web安全字体：Arial、Helvetica、Times New Roman、Georgia、Courier New、Verdana、Tahoma、Trebuchet MS、Impact
- ✅ 通过大小、粗细和颜色创建清晰的视觉层次结构
- ✅ 确保可读性：强烈的对比度、适当大小的文本、干净的排列
- ✅ 保持一致性：重复图案、间距和视觉语言跨幻灯片

#### 色彩调色板选择

**创造性地选择颜色**：
- **超越默认值**：什么颜色真正与这个特定主题匹配？避免自动导航选择。
- **考虑多个角度**：主题、行业、氛围、能量水平、目标受众、品牌身份（如果提到）
- **大胆尝试**：尝试意外的组合 - 医疗保健演示文稿不必是绿色，金融不必是深蓝色
- **构建你的调色板**：选择3-5种可以一起工作的颜色（主色 + 辅助色调 + 强调色）
- **确保对比度**：文本必须清晰地可读于背景上

#### 视觉细节选项

**几何图案**：
- 对角部分分隔符而不是水平分隔符
- 不对称的列宽（30/70、40/60、25/75）
- 旋转的文本标题为90°或270°
- 圆形/六边形图像框架
- 角部的三角形强调形状
- 重叠形状以增加深度

**边框与框架处理**：
- 厚重的单色边框（10-20pt）仅在一侧
- 双线边框，颜色对比
- 角括号而不是完整框架
- L形边框（顶部+左侧或底部+右侧）
- 在标题下方添加强调线条（3-5pt厚）

**字体处理**：
- 极端大小对比（72pt标题与11pt正文）
- 全大写标题，字母间距宽
- 超大尺寸的编号部分
- 使用等宽字体（Courier New）进行数据/统计/技术内容
- 紧凑的字体（Arial Narrow）用于密集信息
- 突出显示文本的轮廓

**图表与数据样式**：
- 单色图表，使用单色强调关键数据
- 水平条形图而不是垂直条形图
- 点图而不是条形图
- 最小网格线或没有网格线
- 数据标签直接在元素上（无需图例）
- 关键指标的超大数字

**布局创新**：
- 全屏图像与文本叠加
- 侧边栏列（20-30%宽度）用于导航/上下文
- 模块化网格系统（3×3、4×4块）
- Z型或F型内容流程
- 在彩色形状上浮动的文本框
- 杂志式多列布局

**背景处理**：
- 占据40-60%幻灯片的实色块
- 垂直或对角线渐变填充
- 分割背景（两种颜色，对角线或垂直）
- 边到边色带
- 负空间作为设计元素

### 布局提示
**当创建包含图表或表格的幻灯片时**：
- **两列布局（首选）**：使用跨全宽的标题，然后在下面两列 - 一列文本/项目符号，另一列突出显示的内容。这提供了更好的平衡，并使图表/表格更易于阅读。使用flexbox和不等列宽（例如，40%/60%分割）来优化每种内容类型的空间。
- **全屏布局**：让突出显示的内容（图表/表格）占据整个幻灯片以获得最大的影响力和可读性
- **永远不要垂直堆叠**：不要将图表/表格放在单列文本下方 - 这会导致可读性和布局问题

### 工作流程
1. **强制性的 - 读取整个文件**：从头到尾完全阅读[`html2pptx.md`](html2pptx.md)。**永远不要设置任何范围限制**。在开始创建演示文稿之前，阅读完整文件内容以获取详细的语法、关键格式化规则和最佳实践。
2. 为每个幻灯片创建一个HTML文件，并具有适当的尺寸（例如，720pt × 405pt用于16:9）
   - 使用`<p>`、`<h1>`-`<h6>`、`<ul>`、`<ol>`对所有文本内容进行标记
   - 使用`class="placeholder"`标记将添加图表/表格的区域（以灰色背景渲染以增强可见性）
   - **至关重要的**：首先使用Sharp将渐变和图标转换为PNG图像，然后再在HTML中引用
   - **布局**：对于包含图表/表格/图像的幻灯片，使用全屏布局或两列布局以获得更好的可读性
3. 创建并运行一个JavaScript文件，使用`[`html2pptx.js](scripts/html2pptx.js)`库将HTML幻灯片转换为PowerPoint，并保存演示文稿
   - 使用`html2pptx()`函数处理每个HTML文件
   - 使用PptxGenJS API将图表和表格添加到占位符区域
   - 使用`pptx.writeFile()`保存演示文稿
4. **视觉验证**：生成缩略图并检查布局问题
   - 创建缩略图网格：`python scripts/thumbnail.py output.pptx workspace/thumbnails --cols 4`
   - 仔细检查缩略图图像：
     - **文本截断**：文本被标题栏、形状或幻灯片边缘截断
     - **文本重叠**：文本与文本或其他形状重叠
     - **定位问题**：内容太靠近幻灯片边界或其他元素
     - **对比度问题**：文本与背景之间的对比度不足
   - 如果发现问题，调整HTML边距/间距/颜色，并重新生成演示文稿
   - 重复操作，直到所有幻灯片在视觉上正确

## 编辑现有的PowerPoint演示文稿

当编辑现有PowerPoint演示文稿中的幻灯片时，您需要使用原始Office Open XML（OOXML）格式。这涉及到解包.pptx文件、编辑XML内容，然后重新打包。

### 工作流程
1. **强制性的 - 读取整个文件**：从头到尾完全阅读[`ooxml.md`](ooxml.md)（约500行）。**永远不要设置任何范围限制**。在开始编辑演示文稿之前，阅读完整文件内容以获取有关OOXML结构和编辑工作流程的详细指导。
2. 解包演示文稿：`python ooxml/scripts/unpack.py <office_file> <output_dir>`
3. 编辑XML文件（主要`ppt/slides/slide{N}.xml`和相关文件）
4. **至关重要的**：在每次编辑后立即进行验证，并修复任何验证错误，然后继续：`python ooxml/scripts/validate.py <dir> --original <file>`
5. 打包最终的演示文稿：`python ooxml/scripts/pack.py <input_directory> <office_file>`

## 使用模板创建新的PowerPoint演示文稿

当您需要创建遵循现有模板设计的演示文稿时，您需要先复制和重新排列模板幻灯片，然后再替换占位符上下文。

### 工作流程
1. **提取模板文本并创建视觉缩略图网格**：
   * 提取文本：`python -m markitdown template.pptx > template-content.md`
   * 读取`template-content.md`：从头到尾阅读整个文件，以了解模板演示文稿的内容。**永远不要设置任何范围限制**。
   * 创建缩略图网格：`python scripts/thumbnail.py template.pptx`
   * 有关更多详细信息，请参阅[创建缩略图网格](#creating-thumbnail-grids)部分

2. **分析模板并将清单保存到文件中**：
   * **视觉分析**：审查缩略图网格以了解幻灯片布局、设计模式和视觉结构
   * 在`template-inventory.md`中创建并保存模板清单文件，内容如下：
     ```markdown
     # 模板清单分析
     **总幻灯片数：[count]**
     **重要提示：幻灯片是0索引（第一张幻灯片=0，最后一张幻灯片=count-1）**

     ## [类别名称]
     - 幻灯片 0：[布局代码（如有）] - 描述/目的
     - 幻灯片 1：[布局代码] - 描述/目的
     - 幻灯片 2：[布局代码] - 描述/目的
     [... 每张幻灯片都必须单独列出，包括其索引 ...]
     ```
   * 使用缩略图网格：参考视觉缩略图以识别：
     - 布局模式（标题幻灯片、内容布局、部分分隔符）
     - 图像占位符位置和数量
     - 在幻灯片组之间的设计一致性
     - 视觉层次结构和结构
   * 此清单文件是必需的，用于在下一步中选择适当的模板

3. **根据模板清单创建演示文稿大纲**：
   * 审查步骤2中提供的可用模板。
   * 选择一个简介或标题模板作为第一张幻灯片。这应该是前几个模板之一。
   * 选择安全、基于文本的布局用于其他幻灯片。
   * **至关重要的**：将布局结构匹配到实际内容：
     - 单列布局：用于统一的叙述或单个主题
     - 两列布局：仅当您有确切的两个不同项目/概念时使用
     - 三列布局：仅当您有确切的三项不同项目/概念时使用
     - 图像+文本布局：仅当您有实际图像要插入时使用
     - 引用布局：仅用于实际引用（带归属），永远不要用于强调
     - 永远不要使用比您的内容更多的占位符的布局
     - 如果您有两个项目，不要将它们强加到三列布局中
     - 如果您有4个项目以上，请考虑将它们拆分到多个幻灯片或使用列表格式
   * 在选择布局之前，实际计算您的内容块
   * 确保所选布局中的每个占位符都将填充有意义的内
