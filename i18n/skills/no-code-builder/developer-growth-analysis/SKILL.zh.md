# 开发者成长分析

这项技能通过分析您的 Claude Code 聊天互动，为您最近的编码工作提供个性化反馈，并识别揭示优势和成长领域的模式。

## 何时使用此技能

当您想要：

- 了解您最近工作的开发模式和习惯
- 识别特定的技术差距或反复出现的问题
- 发现哪些主题需要更深入的学习
- 跟踪您最近项目中的改进领域
- 获得专业成长的可操作建议

这项技能非常适合那些希望在没有等待代码审查的情况下获得关于其成长的有序反馈，并希望从自己的工作历史中获得数据驱动见解的开发者。

## 此技能的功能

此技能对您的开发工作执行四个步骤的分析：

1. **读取您的聊天历史**：访问您过去 24-48 小时内的本地 Claude Code 聊天历史，以了解您正在做什么。

2. **识别开发模式**：分析您正在解决的问题类型、使用的技术、遇到的问题以及您如何处理不同类型的任务。

3. **检测改进领域**：识别表明技能差距、重复的挣扎、效率低下或可能从更深入的知识中受益的领域的模式。

4. **生成个性化报告**：创建一份全面的报告，显示您的工作摘要、识别的改进领域、具体成长建议以及优先级行动项目。

## 如何使用

要求 Claude 分析您最近的编码工作：

```
分析我最近的聊天中的开发者成长
```

或者更具体地说明哪个时间段：

```
分析我从今天开始的工作并提出改进建议
```

该技能将生成一个格式化的报告，包括：

- 您最近工作的概述
- 识别的关键改进领域
- 每个领域的具体建议
- 优先级行动项目
- 寻找学习资源的建议关键词

## 指示

当用户请求分析其开发者成长或最近工作中的编码模式时：

1. **访问聊天历史**

   从 `~/.claude/history.jsonl` 读取聊天历史。此文件是 JSONL 格式，其中每行包含：
   - `display`：用户的消息/请求
   - `project`：正在工作的项目
   - `timestamp`：Unix 时间戳（以毫秒为单位）
   - `pastedContents`：任何粘贴的代码或内容

   根据当前时间戳筛选过去 24-48 小时的条目。

2. **分析工作模式**

   从筛选的聊天中提取和分析以下内容：
   - **项目和领域**：用户正在处理哪些类型的项目？（例如，后端、前端、DevOps、数据等）
   - **使用的技术**：对话中出现了哪些语言、框架和工具？
   - **问题类型**：正在解决哪些类别的问题？（例如，性能优化、调试、功能实现、重构、设置/配置）
   - **遇到的问题**：用户遇到了哪些问题？寻找：
     - 关于类似主题的重复问题
     - 需要多尝试才能解决的问题
     - 表明知识差距的问题
     - 复杂的架构决策
   - **方法模式**：用户如何解决问题？（例如，有条理的、探索性的、实验性的）

3. **识别改进领域**

   根据分析，确定用户可以改进的 3-5 个具体领域。这些应该是：
   - **具体的**（不是像“提高编码技能”这样的模糊说法）
   - **基于证据的**（基于实际的聊天历史）
   - **可操作的**（可以做出的实际改进）
   - **优先级的**（最具影响力的优先）

   优秀的改进领域示例：
   - “高级 TypeScript 模式（泛型、实用类型、类型守卫）- 您在 [特定项目] 中在类型安全性方面遇到了困难”
   - “错误处理和验证 - 我注意到您修补了多个与缺失空检查相关的错误”
   - “Async/await 模式 - 您最近的工作显示了一些竞态条件和时序问题”
   - “数据库查询优化 - 您多次重写了相同的查询”

4. **生成报告**

   创建一个具有以下结构的全面报告：

   ```markdown
   # 您的开发者成长报告

   **报告周期**：[昨天 / 今天 / [自定义日期范围]]
   **最后更新**：[当前日期和时间]

   ## 工作摘要

   [2-3 段总结用户完成了什么工作，涉及的项目，使用的技术，以及整体关注领域]

   示例：
   "在过去 24 小时内，您主要专注于后端开发，处理了三个不同的项目。您的工作涉及 TypeScript、React 和部署基础设施。您处理了从功能实现、调试到架构决策的各种挑战，特别关注 API 设计和数据库优化。"

   ## 改进领域（优先级）

   ### 1. [领域名称]

   **为什么这很重要**：[解释为什么这项技能对用户的工作很重要]

   **我观察到什么**：[来自聊天历史的特定证据，表明这个差距]

   **建议**：[在此领域改进的具体步骤]

   **提升技能所需时间**：[对所需努力的简要估计]

   **搜索关键词**：[建议的搜索词以查找学习资源]

   ---

   [重复 2-4 个附加领域]

   ## 观察到的优势

   [2-3 个要点突出您做得好的事情 - 继续做的事情]

   ## 行动项目

   优先级顺序：
   1. [来自最高优先级改进领域的行动项目]
   2. [来自下一个领域的行动项目]
   3. [来自下一个领域的行动项目]

   ## 推荐的学习重点

   根据您的改进领域，以下是您可以用于查找相关资源的搜索关键词：
   - **改进领域 1**："[搜索词]"
   - **改进领域 2**："[搜索词]"
   - **改进领域 3**："[搜索词]"

   这些术语可以在 HackerNews、dev.to、Medium 或您首选的学习平台上使用。
   ```

5. **呈现完整的报告**

   以干净、易读的格式交付报告，用户可以：
   - 快速扫描关键要点
   - 用于专注的学习规划
   - 在接下来的几周内作为他们改进工作的参考
   - 如果他们想要外部反馈，则与导师分享
   - 使用搜索关键词查找他们自己的学习资源

# 您的开发者成长报告

**报告周期**：2024 年 11 月 9-10 日
**最后更新**：2024 年 11 月 10 日，下午 9:15 UTC

## 工作摘要

在过去两天里，您专注于后端基础设施和 API 开发。您的主要项目是一个开源展示应用程序，您在连接管理、UI 改进和部署配置方面取得了重大进展。您使用 TypeScript、React 和 Node.js，处理了从数据安全到响应式设计的一系列挑战。您的工作在实现功能和解决技术债务之间取得了平衡。

## 改进领域（优先级）

### 1. 高级 TypeScript 模式和类型安全性

**为什么这很重要**：TypeScript 对您的工作至关重要，但利用其高级功能（泛型、实用类型、条件类型、类型守卫）可以显着提高代码可靠性并减少运行时错误。更好的类型安全性在编译时而不是在生产环境中捕获错误。

**我观察到什么**：在您最近的聊天中，您正在处理连接数据结构，并在正确配置身份验证配置时遇到了一些困难。您还不得不迭代联合类型以处理不同的连接状态。有利用歧视联合和类型守卫更有效地应用这些模式的机会。

**建议**：学习 TypeScript 的高级类型系统，特别是实用类型（Omit、Pick、Record）、条件类型和歧视联合。将这些模式应用到您的连接配置处理和身份验证状态管理中。

**提升技能所需时间**：5-8 小时的专注学习和实践

**搜索关键词**："TypeScript 判别联合教程"、"TypeScript 实用类型深入探讨"、"类型守卫最佳实践"

### 2. 安全数据处理和 UI 中的信息隐藏

**为什么这很重要**：您识别并修复了一个安全问题，其中敏感的连接数据被显示在您的控制台中。防止信息泄露对于处理用户凭证和 API 密钥的应用程序至关重要。良好的做法可以防止安全事件和用户信任违规。

**我观察到什么**：您注意到“您的应用程序”页面显示了完整的连接数据，包括身份验证配置。这表明您有良好的安全直觉，下一步是将这纳入您处理敏感信息的默认思维中。

**建议**：审查处理前端应用程序中敏感数据的最佳安全实践。创建在显示之前过滤/屏蔽敏感信息的可重用模式。考虑实现一个安全数据层，该数据层明确允许在 UI 中显示的内容。

**提升技能所需时间**：3-4 小时

**搜索关键词**："前端安全敏感数据处理"、"防止信息泄露 Web 应用程序"、"前端安全凭证管理"

### 3. 组件架构和响应式 UI 模式

**为什么这很重要**：您正在设计需要在不同屏幕大小和用户交互中工作的 UI。强大的组件架构使您能够构建没有错误的复杂 UI，并提高可维护性。

**我观察到什么**：您在“市场”UI（以前称为“浏览工具”）上工作，根据设计图像重新创建它。您还识别并修复了滚动问题，其中内容溢出容器。有加强您对布局包含和响应式设计模式理解的机会。

**建议**：学习 React 组件组合模式和 CSS 布局最佳实践（特别是弹性盒和网格）。关注容器查询和响应式模式，以防止溢出问题。查看组件组合库和设计系统方法。

**提升技能所需时间**：6-10 小时（取决于深度）

**搜索关键词**："React 组件组合模式 2024"、"CSS 弹性盒网格响应式设计"、"防止溢出 CSS 容器查询"

## 观察到的优势

- **安全意识**：您主动识别了数据泄露问题，避免了问题
- **迭代改进**：您有条不紊地处理 UI 要求，提出澄清问题并改进设计
- **全栈能力**：您在后台 API、前端 UI 和部署问题中都能自如地工作
- **问题解决方法**：您将复杂任务分解为可管理的步骤

## 小贴士和最佳实践

- 每周运行此分析一次，以跟踪您随时间改进的轨迹
- 一次专注于一个改进领域，在转向下一个领域之前专注于它几天
- 使用提供的搜索关键词在 HackerNews、dev.to、Medium 或技术博客等平台上查找资源
- 在专注于一个领域一周后回顾此报告，以查看您的工作模式如何改变
- 保存报告以跟踪您的进度，并查看您的技能如何随时间发展

## 如何保持准确性和质量

此技能：
- 分析您从时间戳聊天历史中实际的工作模式
- 生成基于实际项目的基于证据的建议
- 提供搜索关键词以帮助您找到相关学习资源
- 专注于可操作的改进，而不是模糊的反馈
- 根据复杂性提供具体的时间估计
- 优先考虑对您的开发速度影响最大的领域
