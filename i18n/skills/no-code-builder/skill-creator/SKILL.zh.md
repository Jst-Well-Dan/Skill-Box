# 技能创建者

本技能提供创建有效技能的指南。

## 关于技能

技能是模块化、自包含的包，通过提供专业知识、工作流程和工具来扩展 Claude 的功能。将它们视为特定领域或任务的“入职指南”——它们将 Claude 从通用代理转变为具有程序性知识的专业代理，而这些知识任何模型都无法完全拥有。

### 技能提供的内容

1. 专业知识工作流程 - 特定领域中的多步骤程序
2. 工具集成 - 与特定文件格式或 API 一起工作的说明
3. 领域专业知识 - 公司特定知识、模式、业务逻辑
4. 绑定资源 - 复杂和重复性任务的脚本、参考资料和资产

### 技能的构成

每个技能都由一个必需的 SKILL.md 文件和可选的捆绑资源组成：

```
skill-name/
├── SKILL.md (必需)
│   ├── YAML 前端元数据 (必需)
│   │   ├── name: (必需)
│   │   └── description: (必需)
│   └── Markdown 指令 (必需)
└── 捆绑资源 (可选)
    ├── scripts/          - 可执行代码（Python/Bash 等）
    ├── references/       - 需要按需加载到上下文中的文档
    └── assets/           - 用于输出的文件（模板、图标、字体等）
```

#### SKILL.md（必需）

**元数据质量：** YAML 前端元数据中的 `name` 和 `description` 决定了 Claude 将何时使用该技能。请具体说明技能的功能以及何时使用它。使用第三人称（例如，“此技能应在...时使用”而不是“使用此技能”）.

#### 捆绑资源（可选）

##### 脚本 (`scripts/`)

需要确定性和可靠性或反复重写的任务的可执行代码（Python/Bash 等）。

- **何时包含**：当相同的代码被反复重写或需要确定性可靠性时
- **示例**：`scripts/rotate_pdf.py` 用于 PDF 旋转任务
- **好处**：标记高效，确定性，可以在不加载到上下文窗口的情况下执行
- **注意**：脚本可能仍然需要由 Claude 读取以进行修补或针对特定环境的调整

##### 参考资料 (`references/`)

旨在按需加载到上下文中，以告知 Claude 的过程和思考的文档和参考资料材料。

- **何时包含**：Claude 在工作时应参考的文档
- **示例**：`references/finance.md` 用于金融模式，`references/mnda.md` 用于公司 NDA 模板，`references/policies.md` 用于公司政策，`references/api_docs.md` 用于 API 规范
- **用例**：数据库模式、API 文档、领域知识、公司政策、详细的流程指南
- **好处**：保持 SKILL.md 精简，仅在 Claude 确定需要时加载
- **最佳实践**：如果文件很大（>10k 字），请将 grep 搜索模式包含在 SKILL.md 中
- **避免重复**：信息应位于 SKILL.md 或参考资料文件中，而不是两者都包含。除非信息确实是技能的核心，否则优先选择参考资料文件，以保持 SKILL.md 精简，同时使信息易于发现，而不会占用上下文窗口。请将必要的程序性指令和工作流程指南保留在 SKILL.md 中；将详细的参考资料、模式和示例移动到参考资料文件中。

##### 资产 (`assets/`)

不打算加载到上下文，而是用于 Claude 生成的输出中的文件。

- **何时包含**：当技能需要用于最终输出的文件时
- **示例**：`assets/logo.png` 用于品牌资产，`assets/slides.pptx` 用于 PowerPoint 模板，`assets/frontend-template/` 用于 HTML/React 模板，`assets/font.ttf` 用于字体
- **用例**：模板、图像、图标、占位符代码、字体、副本或修改的样本文档
- **好处**：将输出资源与文档分开，使 Claude 能够使用文件而无需加载到上下文

### 渐进式披露设计原则

技能使用三级加载系统来高效管理上下文：

1. **元数据（名称 + 描述）** - 总是存在于上下文中（~100 字）
2. **SKILL.md 正文** - 当技能触发时（<5k 字）
3. **捆绑资源** - Claude 需要时（无限*）

*无限，因为脚本可以在不读取上下文窗口的情况下执行。

## 技能创建流程

要创建技能，按照“技能创建流程”的顺序进行，只有当有明确的理由时才跳过步骤。

### 步骤 1：通过具体示例了解技能

只有当技能的使用模式已经清楚地理解时，才跳过此步骤。即使在处理现有技能时，它仍然很有价值。

为了创建一个有效的技能，清楚地了解技能将如何被使用的具体示例。这种理解可以来自直接用户示例或通过用户反馈验证的生成示例。

例如，当构建图像编辑技能时，相关问题包括：

- “图像编辑技能应支持哪些功能？编辑、旋转，还有其他吗？）
- “你能给我一些这个技能如何被使用的例子吗？
- “我想象用户会要求像‘从这张图片中移除红眼’或‘旋转这张图片’这样的事情。你还有其他想象这个技能会被如何使用的方法吗？
- “用户会说什么才能触发这个技能？

为了避免用户感到不知所措，避免在一条消息中提出太多问题。从最重要的问题开始，根据需要跟进以提高效果。

当对技能应支持的功能有明确的认识时，完成此步骤。

### 步骤 2：规划可重用技能内容

为了将具体示例转换为有效的技能，通过以下方式分析每个示例：

1. 考虑如何从头开始执行示例
2. 确定在执行这些工作流程时，哪些脚本、参考资料和资产会有所帮助

示例：当构建处理查询“帮我旋转这个 PDF”的 `pdf-editor` 技能时，分析显示：

1. 旋转 PDF 需要每次都重写相同的代码
2. 存储在技能中的 `scripts/rotate_pdf.py` 脚本会有所帮助

示例：当为处理查询“为我构建一个待办事项应用”或“为我构建一个跟踪我的步数的仪表板”的 `frontend-webapp-builder` 技能设计时，分析显示：

1. 编写前端 Web 应用需要每次都编写相同的 HTML/React 模板
2. 存储在技能中的 `assets/hello-world/` 模板包含 HTML/React 项目的占位符文件将会有所帮助

示例：当构建处理查询“今天有多少用户登录了？”的 `big-query` 技能时，分析显示：

1. 查询 BigQuery 需要每次都重新发现表模式和关系
2. 存储在技能中的 `references/schema.md` 文件记录表模式将会有所帮助

为了确定技能的内容，分析每个具体示例以创建一个包含以下内容的可重用资源的列表：脚本、参考资料和资产。

### 步骤 3：初始化技能

到此为止，是时候实际创建技能了。

只有当正在开发的技能已经存在且需要进行迭代或打包时，才跳过此步骤。在这种情况下，继续到下一步。

当从头开始创建新技能时，始终运行 `init_skill.py` 脚本。该脚本方便地生成一个新的模板技能目录，该目录自动包含技能所需的全部内容，使技能创建过程更高效、更可靠。

用法：

```bash
scripts/init_skill.py <skill-name> --path <output-directory>
```

该脚本：

- 在指定的路径创建技能目录
- 生成 SKILL.md 模板，包括适当的元数据和 TODO 占位符
- 创建示例资源目录：`scripts/`、`references/` 和 `assets/`
- 在每个目录中添加示例文件，这些文件可以根据需要进行自定义或删除

初始化后，根据需要自定义或删除生成的 SKILL.md 和示例文件。

### 步骤 4：编辑技能

在编辑（新创建的或现有的）技能时，请记住技能是为另一个 Claude 实例使用的。专注于包含对 Claude 有益且不明显的信息。考虑哪些程序性知识、领域特定细节或可重用资产将帮助另一个 Claude 实例更有效地执行这些任务。

#### 从可重用技能内容开始

为了开始实施，从上述已确定的可重用资源开始：`scripts/`、`references/` 和 `assets/` 文件。请注意，此步骤可能需要用户输入。例如，在实施 `brand-guidelines` 技能时，用户可能需要提供存储在 `assets/` 中的品牌资产或模板，或存储在 `references/` 中的文档。

同时，删除任何不需要的示例文件和目录。初始化脚本在 `scripts/`、`references/` 和 `assets/` 中创建示例文件以演示结构，但大多数技能不需要所有这些。

#### 更新 SKILL.md

**写作风格：** 使用**祈使/不定式形式**（动词开头指令），而不是第二人称。使用客观、指导性的语言（例如，“要完成 X，执行 Y”而不是“你应该做 X”或“如果你需要做 X”）。这保持了 AI 消费的连贯性和清晰度。

要完成 SKILL.md，回答以下问题：

1. 技能的目的是什么，用几句话概括？
2. 应该何时使用技能？
3. 实际上，Claude 应该如何使用该技能？上述开发的所有可重用技能内容都应被引用，以便 Claude 知道如何使用它们。

### 步骤 5：打包技能

技能准备好后，应打包成可分发 zip 文件，与用户共享。打包过程首先自动验证技能以确保其符合所有要求：

```bash
scripts/package_skill.py <path/to/skill-folder>
```

可选输出目录指定：

```bash
scripts/package_skill.py <path/to/skill-folder> ./dist
```

打包脚本将：

1. **验证**技能自动，检查：
   - YAML 前端元数据格式和必需字段
   - 技能命名约定和目录结构
   - 描述的完整性和质量
   - 文件组织和资源引用
2. **打包**技能如果验证通过，创建一个以技能命名的 zip 文件（例如，`my-skill.zip`），包含所有文件，并保持正确的目录结构以供分发。

如果验证失败，脚本将报告错误并退出而不创建包。修复任何验证错误，然后再次运行打包命令。

### 步骤 6：迭代

在测试技能后，用户可能要求改进。通常，这发生在使用技能之后，并提供了关于技能如何表现的新鲜上下文。

**迭代工作流程：**

1. 在实际任务中使用技能
2. 注意到挑战或低效之处
3. 确定如何更新 SKILL.md 或捆绑资源
4. 实施更改并再次测试
