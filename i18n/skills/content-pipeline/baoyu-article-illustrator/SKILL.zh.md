# 文章插图工具

分析文章，识别插图位置，生成具有类型 × 风格一致性的图像。

## 使用方法

```bash
# 根据内容自动选择类型和风格
/baoyu-article-illustrator 路径/to/article.md

# 指定类型
/baoyu-article-illustrator 路径/to/article.md --type infographic

# 指定风格
/baoyu-article-illustrator 路径/to/article.md --style blueprint

# 组合类型和风格
/baoyu-article-illustrator 路径/to/article.md --type flowchart --style notion

# 指定密度
/baoyu-article-illustrator 路径/to/article.md --density rich

# 直接输入内容
/baoyu-article-illustrator
[粘贴内容]
```

## 选项

| 选项 | 描述 |
|------|------|
| `--type <name>` | 插图类型（见类型画廊） |
| `--style <name>` | 视觉风格（见风格画廊） |
| `--density <level>` | 图像数量：最少 / 平衡 / 丰富 |

## 两个维度

| 维度 | 控制 | 示例 |
|------|------|------|
| **类型** | 信息结构，内容布局 | infographic，场景，流程图，比较，框架，时间线 |
| **风格** | 视觉美学，颜色，氛围 | notion，温暖，简约，蓝图，水彩，优雅 |

类型 × 风格可以自由组合。例如：`--type infographic --style blueprint` 创建具有方案美学的技术数据可视化。

## 类型画廊

| 类型 | 描述 | 最佳使用场景 |
|------|------|--------------|
| `infographic` | 数据可视化，图表，指标 | 技术文章，数据分析，比较 |
| `scene` | 氛围插图，氛围渲染 | 叙事文章，个人故事，情感内容 |
| `flowchart` | 流程图，步骤可视化 | 指南，工作流程，决策树 |
| `comparison` | 并列，前后对比 | 产品比较，选项评估 |
| `framework` | 概念图，关系图 | 方法论，模型，架构设计 |
| `timeline` | 时间线 | 历史，项目进度，演变 |

## 密度选项

| 密度 | 数量 | 描述 |
|------|------|------|
| `minimal` | 1-2 | 核心概念 |
| `balanced`（默认）| 3-5 | 主要部分覆盖 |
| `rich` | 6+ | 丰富视觉支持 |

## 风格画廊

| 风格 | 描述 | 最佳使用场景 |
|------|------|--------------|
| `notion`（默认）| 极简主义手绘线条艺术 | 知识分享，SaaS，生产力 |
| `elegant` | 精致，复杂 | 商业，思想领导力 |
| `warm` | 友好，亲切 | 个人成长，生活方式，教育 |
| `minimal` | 极简，禅意 | 哲学，极简主义，核心概念 |
| `blueprint` | 技术方案图 | 建筑，系统设计，工程 |
| `watercolor` | 软件艺术，自然温暖 | 生活方式，旅行，创意 |
| `editorial` | 杂志风格信息图 | 科技解释，新闻 |
| `scientific` | 学术精确图表 | 生物学，化学，技术研究 |

完整风格规范：`references/styles/<style>.md`

## 输出目录

```
illustrations/{主题缩略语}/
├── source-{缩略语}.{扩展名}
├── outline.md
├── prompts/
│   └── illustration-{缩略语}.md
└── NN-{类型}-{缩略语}.png
```

**缩略语**：提取 2-4 个单词的主题，使用短横线分隔。
**冲突**：如果存在，则附加 `-YYYYMMDD-HHMMSS`。

模式：`references/config/preferences-schema.md`

**1.2 分析内容**

阅读文章，检测语言，分类内容。

| 分析 | 描述 |
|------|------|
| 内容类型 | 技术 / 指南 / 方法论 / 叙事 |
| 核心论点 | 2-5 个必须可视化的主要论点 |
| 视觉机会 | 插图增加价值的位置 |
| 推荐类型 | 根据内容信号 |
| 推荐密度 | 根据文章长度和复杂性 |

**1.3 提取核心论点**

提取 2-5 个必须可视化的核心论点：
- 主要论点
- 读者需要的关键概念
- 比较和对比
- 提出的框架/模型

**CRITICAL**：如果文章使用隐喻（例如，“电锯切西瓜”），不要直接描绘。可视化 **底层概念** 代替。

**1.4 识别位置**

**要描绘什么**：
- 核心论点（必需）
- 需要可视化的抽象概念
- 数据比较，指标
- 流程，工作流程

**不要描绘什么**：
- 直接描绘隐喻
- 没有信息的装饰性场景
- 通用插图

### 第 2 步：确认设置 ⚠️

**不要跳过**。使用 AskUserQuestion 在一次调用中提出 3-4 个问题。

**问题 1：插图类型**

根据内容分析，推荐类型：
- [根据信号推荐的类型]（推荐）

- scene - 氛围，氛围渲染
- flowchart - 流程，步骤
- comparison - 并列对比
- framework - 概念关系
- timeline - 时间线
- mixed - 组合多个类型

**问题 2：密度**

- minimal（1-2 个图像）- 核心概念
- balanced（3-5 个图像）（推荐）- 主要部分
- rich（6+ 个图像）- 丰富视觉支持

**问题 3：风格**

根据推荐的类型，建议兼容的风格（见类型 × 风格兼容性矩阵）：
- [推荐类型最佳兼容风格]（推荐）
- [其他高度兼容风格：✓✓ 来自矩阵]
- [兼容风格：✓ 来自矩阵]

**问题 4**（仅当源 ≠ 用户语言时）：
- 语言：源语言 / 用户语言

### 第 3 步：生成大纲

根据已确认的类型 + 密度 + 风格，生成插图大纲。

**大纲格式** (`outline.md`）：

```yaml
---
type: infographic
density: balanced
style: blueprint
image_count: 4
---

## 插图 1

**位置**：[部分] / [段落]
**目的**：[为什么这个插图有帮助]
**视觉内容**：[要展示的内容]
**类型应用**：[如何应用类型]
**文件名**：01-infographic-concept-name.png

## 插图 2
...
```

**大纲要求**：
- 每个插图位置都有内容需求的支持
- 类型在所有插图上一致应用
- 风格特征反映在视觉描述中
- 数量与密度选择匹配

### 第 4 步：生成图像

**4.1 创建提示**

遵循以下提示构建原则。每个保存到 `prompts/illustration-{slug}.md`。

**4.2 选择生成技能**

检查可用的图像生成技能。如果有多个，请用户选择。

**4.3 应用水印**（如果首选项中启用）

## 提示构建

### 原则

好的提示必须包括：

1. **首先描述布局结构**：描述构图，区域，流动方向
2. **具体数据/标签**：使用实际的数字，文章中的术语
3. **视觉关系**：元素如何连接
4. **语义颜色**：基于意义的颜色选择（红色=警告，绿色=高效）
5. **风格特征**：线条处理，纹理，氛围
6. **长宽比**：以比例和复杂度级别结束

### 类型特定提示

**Infographic**：
```plaintext
[标题] - 数据可视化

布局：[网格/辐射/层次]

区域：
- 区域 1：[具有特定值的指标]
- 区域 2：[与指标的对比]
- 区域 3：[总结/结论]

标签：[特定的数字，百分比，文章中的术语]
颜色：[语义颜色映射]
风格：[风格特征]
长宽比：16:9
```

**Scene**：
```plaintext
[标题] - 氛围场景

焦点：[主要主题]
氛围：[照明，氛围，环境]
氛围：[要传达的情感]
颜色温度：[温暖/凉爽/中性]
风格：[风格特征]
长宽比：16:9
```

**Flowchart**：
```plaintext
[标题] - 流程图

布局：[从左到右/从上到下/圆形]

步骤：
1. [步骤名称] - [简要描述]
2. [步骤名称] - [简要描述]
...

连接：[箭头类型，决策点]
风格：[风格特征]
长宽比：16:9
```

**Comparison**：
```plaintext
[标题] - 比较视图

左侧 - [选项 A]：
- [要点 1]
- [要点 2]

右侧 - [选项 B]：
- [要点 1]
- [要点 2]

分隔符：[视觉分隔符]
风格：[风格特征]
长宽比：16:9
```

**Framework**：
```plaintext
[标题] - 概念框架

结构：[层次/网络/矩阵]

节点：
- [概念 1] - [角色]
- [概念 2] - [角色]

关系：[节点如何连接]
风格：[风格特征]
长宽比：16:9
```

**Timeline**：
```plaintext
[标题] - 时间线视图

方向：[水平/垂直]

事件：
- [日期/时间段 1]：[里程碑]
- [日期/时间段 2]：[里程碑]

标记：[视觉指示器]
风格：[风格特征]
长宽比：16:9
```

### 要避免的内容

- 模糊的描述（“一张好图”）
- 直接描绘隐喻
- 缺少具体的标签/注释
- 通用装饰性元素
