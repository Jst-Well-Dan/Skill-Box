# Obsidian Canvas Creator

将文本内容转换为支持思维导图和自由布局的结构化 Obsidian Canvas 文件。

## 何时使用此技能

- 用户请求从文本创建画布、思维导图或视觉图表
- 用户想要在空间上组织信息
- 用户提及 "Obsidian Canvas" 或类似的可视化工具
- 将结构化内容（文章、笔记、大纲）转换为视觉格式

## 核心工作流程

### 1. 分析内容

阅读和理解输入内容：
- 识别主要主题和层次关系
- 提取要点、事实和支撑细节
- 注意任何现有结构（标题、列表、部分）

### 2. 确定布局类型

询问用户选择或根据上下文推断：

**思维导图布局：**
- 从中心辐射的结构
- 父子关系
- 清晰的层次
- 适用于：头脑风暴、主题探索、层次内容

**自由布局：**
- 自定义定位
- 灵活的关联
- 多种连接类型
- 适用于：复杂网络、非层次内容、自定义排列

### 3. 规划结构

**对于思维导图：**
- 识别中心概念（根节点）
- 绘制主要分支（主要主题）
- 组织次要分支（子主题）
- 定位叶节点（细节）

**对于自由布局：**
- 将相关概念分组
- 识别连接模式
- 规划空间区域
- 考虑视觉流程

### 4. 生成画布

创建遵循画布规范的 JSON：

**节点创建：**
- 分配唯一的 8-12 位十六进制 ID
- 根据内容长度设置适当的尺寸
- 应用一致的调色板
- 确保没有坐标重叠

**边创建：**
- 连接父子关系
- 使用适当的箭头样式
- 为复杂关系添加标签
- 选择线条样式（直线用于层次，曲线用于交叉引用）

**分组（可选）：**
- 为相关节点创建视觉容器
- 使用细微的背景颜色
- 添加描述性标签

### 5. 应用布局算法

**思维导图布局计算：**

参阅 `references/layout-algorithms.md` 以获取详细算法。关键原则：

- 将根节点置于 (0, 0)
- 径向分布主要节点
- 根据兄弟数量空间化次要节点
- 保持最小间距：水平 320px，垂直 200px

**自由布局原则：**

- 从逻辑分组开始
- 使用清晰的分隔定位组
- 使用曲线边连接组间
- 在画布上平衡视觉重量

### 6. 验证和输出

在输出之前：

**验证清单：**
- 所有节点都有唯一的 ID
- 没有坐标重叠（检查距离 > 节点尺寸 + 间距）
- 所有边引用有效的节点 ID
- （如果有的话）分组有标签
- 颜色使用一致的格式（十六进制或预设数字）
- JSON 正确转义（中文引号：『』用于双引号，「」用于单引号）

**输出格式：**
- 完整、有效的 JSON 画布文件
- 没有额外的解释文本
- 直接可导入到 Obsidian

## 节点尺寸指南

**基于文本长度的大小：**
- 短文本（<30 个字符）：220 × 100 px
- 中等文本（30-60 个字符）：260 × 120 px
- 长文本（60-100 个字符）：320 × 140 px
- 非常长的文本（>100 个字符）：320 × 180 px

## 调色板

**预设颜色（推荐）：**
- `"1"` - 红色（警告，重要）
- `"2"` - 橙色（行动项）
- `"3"` - 黄色（问题，备注）
- `"4"` - 绿色（积极，完成）
- `"5"` - 青色（信息，细节）
- `"6"` - 紫色（概念，抽象）

**自定义十六进制颜色：**
用于品牌一致性或特定主题。始终使用大写格式：`"#4A90E2"`

## 临界规则

1. **引号处理：**
   - 中文双引号 → 『』
   - 中文单引号 → 「」
   - 英文双引号 → `\"`

2. **ID 生成：**
   - 8-12 位随机十六进制字符串
   - 必须在所有节点和边中唯一

3. **Z-索引顺序：**
   - 首先输出组（底层）
   - 然后子组
   - 最后是文本/链接节点（顶层）

4. **间距要求：**
   - 最小水平间距：节点中心之间 320px
   - 最小垂直间距：节点中心之间 200px
   - 在计算时考虑节点尺寸

5. **JSON 结构：**
   - 最高级别仅包含 `nodes` 和 `edges` 数组
   - 没有额外的包装对象
   - 输出中没有注释

## 示例

### 简单思维导图请求
用户："创建关于太阳系行星的思维导图"

过程：
1. 识别中心："太阳系"
2. 主要分支：内行星、外行星、矮行星
3. 次级节点：各个行星的关键事实
4. 应用径向布局
5. 生成具有适当间距的 JSON

### 自由内容请求
用户："将这篇文章转换成画布" + [文章文本]

过程：
1. 提取文章结构（引言、正文部分、结论）
2. 识别关键概念和关系
3. 在空间上分组相关部分
4. 使用标签边连接
5. 应用具有清晰区域的自由布局

## 质量画布的技巧

1. **保持文本简洁**：每个节点应可扫描（首选 <2 行）
2. **使用层次**：按重要性和关系分组
3. **平衡画布**：分配节点以避免聚集
4. **战略颜色**：使用颜色来编码含义，而不仅仅是装饰
5. **有意义的连接**：仅添加阐明关系的边
6. **在 Obsidian 中测试**：验证输出是否正确打开

## 避免的常见错误

- 重叠的节点（始终检查距离）
- 不一致的引号转义（破坏 JSON 解析）
- 缺少组标签（导致侧边栏导航问题）
- 节点中太多文本（使用文件节点进行长内容）
- 重复的 ID（每个都必须是唯一的）
- 未连接的节点（除非有意为之）
